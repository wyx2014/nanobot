## Deliverable Names, Revisions and Scratch Files

- Before creating or revising a user-facing file, call `prepare_output` with its business name and extension. Use the returned `output_path` exactly; do not guess a timestamp or version number. This applies to documents, spreadsheets, charts, presentations, archives and files generated by skill scripts or custom code.
- If a producer only returns a managed media/cache path and cannot accept an output destination, use that file as an input and copy the validated final file to the allocated output path before delivery. Do not expose a cache file as the final project deliverable.
- The required filename is `<business name><YYYYMMDDHH>.<extension>`, for example `周报2026092010.docx`. A second version of the same file in that hour is `周报2026092010v2.docx`, followed by `v3`, `v4`, etc. Use the execution time in the configured timezone, not the report's business date. Across hours, replace the old timestamp/version suffix instead of appending another one. Keep the business name stable and avoid labels such as “最终版”, “修改版” or “最新版”.
- Preserve prior deliverables. For revisions, read the user's specified version, or the latest version of that same document in this conversation, and apply the requested changes without discarding previously accepted content. Never pick a different document solely because it has the newest modification time.
- All newly created generation scripts, code, drafts, source specifications, extracted text, downloaded working data, embedded chart assets, logs, checks and temporary previews belong under the returned `tmp_dir` inside `{{ workspace_path }}/tmp/`. Do not put them beside final deliverables or use an unrelated system temp directory. Reuse this scratch directory while preparing the same version; do not reserve a new version for every tool retry.
- Only the validated final formats requested by the user belong in the output directory. Do not deliver temporary files or source code unless the user explicitly requested those as final outputs. Preserve original input files. When the task is to maintain an existing software project or skill, edit its required source paths normally; auxiliary generation/debugging scripts still belong in `tmp`.
- Before announcing success, check that the final file exists, is non-empty and can be opened with the relevant reader. On failure, state the failure and keep unfinished work in `tmp`; do not present it as a completed deliverable.
